# Устройство программы

Программа разделяет интерфейс Qt и проверяемые модули Python для состояния проекта, сканирования, обработки файлов, предложений названий, хранения данных и экспорта порядка публикации. Долгое сканирование и операции с медиа выполняются вне потока интерфейса.

Принятое поведение описано в `docs/PLAN.md`. Выполняйте по одному заданию из локального списка `.work-memory/TASKS.md`. Проекты и журналы остаются в локальных данных приложения; автоматические проверки используют искусственные примеры.

Программа не отправляет файлы в Telegram. Отдельный загрузчик Telegram Media Sender принимает локальный версионированный файл `publication-plan.json`.

FFprobe показывает звуковые дорожки. FFmpeg извлекает выбранную дорожку копированием потока (`-c:a copy`) без перекодирования. Готовый файл устанавливается только после проверки дорожки, кодека, длительности и полного чтения. В выпуск нужно включить проверенную пару FFmpeg/FFprobe и обязательные уведомления о лицензии.

Копирование и архивирование записываются в отдельный локальный журнал SQLite; у каждого шага есть контрольная сумма и возможность безопасно продолжить после перезапуска. Удаление оригинала — отдельное выключенное по умолчанию действие: нужны точный утверждённый список путей, повторная проверка готового аудио, неизменность оригинала и подтверждение, что остальные выбранные данные из контейнера сохранены.

Названия предлагает закреплённая модель Qwen3-4B Q4_K_M (2 497 280 256 байт; SHA-256 указан в `local_model.py`) через закреплённую версию llama.cpp. Интернет нужен только для первой загрузки модели. Загрузку можно продолжить по HTTP Range; модель устанавливается только после проверки размера и SHA-256. Предложения генерируются локальным процессом, а текст передаётся ему через приватный временный файл.
