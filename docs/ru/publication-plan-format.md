# Формат `publication-plan.json`

Файл передаёт TelegramMediaSender порядок публикации из Study Archive Prep. Он не содержит исходные абсолютные пути, локальные журналы, содержимое SRT, параметры Telegram или секреты. Sender открывает его как описание очереди, сверяет каждый путь, размер и SHA-256 и показывает полный предварительный просмотр до отправки.

## Версия 1

Файл UTF-8 JSON с завершающим переводом строки. Неизвестная версия должна остановить импорт.

```json
{
  "format": "study-archive-publication-plan",
  "schema_version": 1,
  "project_id": "00000000-0000-4000-8000-000000000001",
  "revision": 1,
  "items": [
    {"id":"00000000-0000-4000-8000-000000000002","kind":"text","week":1,"date":null,"text":"Неделя 1 03.08 - 08.08"},
    {"id":"00000000-0000-4000-8000-000000000003","kind":"file","week":1,"date":null,"path":"Неделя 1/Неделя_01_Материалы_на_неделю.zip","name":"Неделя_01_Материалы_на_неделю.zip","size":1234,"sha256":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"},
    {"id":"00000000-0000-4000-8000-000000000004","kind":"text","week":1,"date":"2026-08-03","text":"2026-08-03"}
  ]
}
```

### Поля

- `format` — постоянный маркер `study-archive-publication-plan`.
- `schema_version` — целое число `1`.
- `project_id` — постоянный UUID проекта.
- `revision` — положительная редакция публикационного плана.
- `items` — упорядоченный список сообщений и файлов; список задаёт порядок отправки.
- У каждого элемента есть уникальный UUID `id`, `kind` (`text` или `file`), номер `week` и `date` (`YYYY-MM-DD` либо `null`).
- Текстовый элемент содержит точное поле `text`.
- Файловый элемент содержит безопасный относительный `path`, его `name`, размер в байтах `size` и SHA-256 в нижнем регистре.

Путь разрешается только внутри выбранной папки результата. Абсолютные пути, `..`, символические ссылки, пропавшие файлы, несовпадение размера/SHA и неизвестная версия блокируют импорт. Сам `publication-plan.json` не является элементом отправки. Повторный экспорт для того же проекта/редакции детерминирован.

ZIP с материалами считается одним файлом очереди. Его участники не экспортируются отдельно. Различающиеся SRT остаются отдельными пунктами. Отправитель обязан сохранить порядок элементов и не сортировать список повторно.
