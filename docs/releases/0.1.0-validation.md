# Development build 0.1.0 — validation report

This report records the local Apple Silicon development build. It is not a statement that a public release is notarized or approved for distribution.

## Build

- macOS 15.7.4, Apple Silicon (`arm64`); minimum target macOS 13.0.
- Python 3.12.14, PyInstaller 6.19.0, PySide6 6.10.2.
- FFmpeg/ffprobe 8.1.3, built from the pinned official source archive as LGPL 2.1 or later, without GPL, nonfree, network, or autodetected external components.
- llama.cpp commit `7fe450e19305b828c199d602c23a8337aaa1f03b`; Metal enabled, OpenSSL disabled.
- Model downloaded separately and verified against the pinned size and SHA-256 in `THIRD_PARTY_NOTICES.md`; it is not in Git or the app archive.

## Checks performed

- 122 automated tests passed; one optional real-FFmpeg test was skipped because the normal test environment intentionally has no system FFmpeg.
- Separately generated a synthetic MKV with video and AAC, extracted the audio with the release FFmpeg, confirmed the codec remained AAC, and fully read the resulting M4A.
- Built the `.app`, verified `--version`, verified its ad-hoc code signature, extracted the ZIP, and launched the extracted app with an empty data directory. The app created a fresh local SQLite database and stayed open.
- Confirmed the packaged FFmpeg, ffprobe, and llama CLI start; checked the FFmpeg and llama CLI deployment target; checked that the packaged FFmpeg and llama CLI do not contain the local checkout path.
- Verified the archive SHA-256 using the supplied checksum file.

## Known release limits

- This Mac has no Developer ID signing identity. The app is ad-hoc signed and not notarized; macOS may require the user to approve it after download.
- Qt for Python and Qt source links and license texts are recorded, but their large upstream source archives are not embedded in this development ZIP. Complete and review the LGPL relinking/source package before publishing a binary release.
- A five-example synthetic Russian/German title check produced two usable short titles; three outputs were declined by the stricter length/language filter. An earlier unfiltered botanical suggestion was inaccurate. The app presents any accepted title for user correction and confirmation. Evaluate title quality on a broader synthetic set before treating this feature as release-ready.
- The full interactive GUI path was smoke-launched with a fresh profile; file-selection and end-to-end archive workflow still require manual QA against the release app before a public 1.0.0 release.
