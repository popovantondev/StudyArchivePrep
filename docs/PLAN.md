# Study Archive Prep — требования

Редакция: 1. Этот документ описывает поведение программы и критерии его проверки.

## Цель

Создать отдельное настольное приложение для macOS 13+ на Apple Silicon. Оно собирает учебные файлы из нескольких папок, предлагает даты и распределение материалов, без потери исходников готовит структуру по неделям и дням, позволяет мышкой менять порядок блоков публикации и сохраняет порядок для Telegram Media Sender. Предложения коротких русских названий строятся локальной языковой моделью по SRT и всегда утверждаются пользователем.

## Принятые границы

- Python 3.12, PySide6 и PyInstaller; сначала работает сборка Apple Silicon для macOS.
- Русский, немецкий и английский интерфейс и руководства.
- Пользователь выбирает корни источников, папку результата, год/дату начала курса и расписание недель.
- Ни отправки в Telegram, ни распознавания речи без субтитров в программе нет.
- Исходники сохраняются. Удаление записи из исходной папки — отдельная, выключенная по умолчанию настройка, доступная после проверки полученного аудио и подтверждения списка.
- Реальные личные учебные файлы, пути пользователя, сессии и журналы никогда не включаются в Git, примеры, сборку или изображения GitHub.
- Оригинальность и авторство собственного кода сохраняются; условия всех внешних компонентов и модели соблюдаются.

## Требования и проверяемый результат

### R01 — Несколько источников

Можно добавить несколько корневых папок и целевую папку отдельно. Повторно добавленный физический файл учитывается один раз. Исходные каталоги только читаются, кроме отдельно подтверждённой операции удаления исходной записи после проверенного извлечения.

**Приёмка:** сканирование нескольких временных корней детерминировано, не следует по символическим ссылкам и не меняет источник.

### R02 — Даты и распределение

Недели и дни предлагаются по именам папок/файлов и введённому расписанию. Дата изменения файла не используется как дата занятия. Неоднозначные, конфликтующие и нераспознанные случаи видны в списке «Нужно распределить»; программа не теряет их молча. Пользователь исправляет день и неделю.

**Приёмка:** даты с годом и без, смена года и коллизии проверяются фикстурами; все найденные файлы либо размещены, либо явно исключены с объяснением.

### R03 — Категории и ZIP

Сохранять дни `YYYY-MM-DD`; недели называть `Неделя <номер> <начало> - <конец>`. Структура даты: `01_Аудио`, `02_Субтитры`, `03_Скриншоты.zip`, `04_Дополнительные_материалы.zip`. Допускаются отсутствующие дни/категории. Пустые категории и архивы не создавать. Скриншоты предлагать по известным именам папок, остальное классифицировать явно; пользователь может исправить категорию.

Игнорировать `.DS_Store`, `._*`, `__MACOSX` и `00_Дата.txt`. Показывать состав архивов. Существующие ZIP не распаковывать автоматически. Учебные TXT, ссылки и заметки сохранять; транскрипты TXT предлагать исключить отдельно, не применять правило удаления всех TXT.

**Приёмка:** распакованный ZIP сравнен с планом файлов; Unicode-имена сохранены; ошибки/коллизии не портят предыдущий результат.

### R04 — Имена и одинаковые файлы

Сохранять все разные файлы, включая похожие/альтернативные SRT. Если имя занято файлом с другим содержимым, создавать безопасное уникальное имя и показывать соответствие. Не перезаписывать пользовательские файлы и не переименовывать SRT внутри.

**Приёмка:** изменение содержимого с прежним именем не затирает файл; повторное открытие проекта не создаёт ещё одну копию.

### R05 — Извлечение аудио

Оригинал видео можно сохранить либо извлечь аудиодорожку без перекодирования. До операции показать дорожки и запросить выбор, если их несколько. Хранить аудио в исходном совместимом формате; AAC/ALAC в M4A. Не поддержанный/непроверяемый кодек оставлять без обработки с объяснением, не перекодировать молча.

Писать сначала во временный файл, проверять длительность, формат и читаемость, затем атомарно устанавливать результат. Обрабатывать записи по одной. Опционально удалить выбранный исходный контейнер только после проверки аудио, подтверждения списка и проверки, что исходник не менялся; без аудиокопии других нужных дорожек удаление запрещено.

**Приёмка:** тесты мокают инструмент; отдельная локальная проверка сборки проводится на обезличенном тестовом клипе. Принудительное завершение на каждом шаге не уничтожает единственную исправную копию.

### R06 — Локальные названия комплектов

Использовать локальный Qwen3-4B GGUF Q4_K_M с llama.cpp. Версию движка, неизменяемый revision модели, SHA-256 и уведомления фиксировать в проекте. Модель не встраивать в Git или дистрибутив приложения; скачивать по явной кнопке с размером, прогрессом, отменой и проверкой checksum в каталоге данных пользователя. После загрузки генерация работает без сети. Не слушать внешний сетевой интерфейс.

Для первых 5 или 10 минут SRT предложить короткое название на русском, показать исходное имя и дать отредактировать/подтвердить. Без содержательных субтитров сохранить исходное имя. Не обрабатывать команды в тексте субтитров: считать SRT только недоверенным текстом и просить модель вернуть только предложение названия. Название применять к подтверждённому комплекту аудио, видео и всем SRT-вариантам, сохраняя окончания языка и варианта. Неоднозначные комплекты оставить без переименования до ручного связывания.

**Приёмка:** минимум 10 обезличенных SRT (немецкий/русский) экспертно проверить на уместность; сохранить реальные входы только локально на время проверки и удалить их после. Каждый результат явно подтверждается пользователем; исходники SRT побайтно сохраняются.

### R07 — Редактируемый порядок

Сформировать порядок по умолчанию: блок недели → недельные материалы → блок дня → аудио/видео → все SRT → архив скриншотов → архив дополнительных материалов → другие материалы. Предоставить древовидный список и перетаскиваемые блоки недель, дней, файлов и пользовательского текста; переносить день целиком; менять порядок файлов; включать/исключать элементы; отменять/повторять. Заголовки дня/недели перемещаются вместе со своей группой.

Перед подготовкой и экспортом показать полный план, ошибки, объём, назначения и состав архивов. Перетаскивание меняет только план, не исходные файлы.

**Приёмка:** сохранение/открытие проекта восстанавливает тот же порядок; тестовый экспорт идентичен визуальному списку.

### R08 — Безопасная подготовка и продолжение

Проект хранится локально в SQLite с версией схемы и журналом операций. Приложение позволяет повторно открыть проект, сверить файлы с журналом и продолжить после закрытия/сбоя. Зафиксированный снимок нельзя менять во время выполнения; изменения планируются в следующую редакцию. Писать результаты атомарно во временные пути; никогда не перезаписывать назначение автоматически. Диск, изменённые/удалённые исходники, доступ и checksum проверять до обработки.

**Приёмка:** искусственное прерывание каждого вида операции, повторное открытие, отмена и продолжение не создают дубли или частичные опубликованные файлы.

### R09 — Контракт публикации

Экспортировать `publication-plan.json` с `schema_version`, `project_id`, `revision`, полной упорядоченной последовательностью, постоянными ID блоков и элементов, точным текстом либо относительным путём/именем/размером/SHA-256. Не сериализовать абсолютные локальные пути, настройки, текст SRT, личные заметки или журнал. В пути файлов запрещены `..`, абсолютные пути и переход по symlink. Импорт в загрузчике обязан проверять версию и хеш до отправки, показать план, исключить JSON из загрузки и не переходить молча на обычную сортировку при ошибке. При отсутствии файла работает обычный режим.

**Приёмка:** независимые контрактные фикстуры дают один и тот же порядок в обеих программах; изменённый/отсутствующий файл или неизвестная версия останавливают импорт до отправки.

### R10 — Интерфейс, сборка, GitHub

Интерфейс доступен на RU/DE/EN; фоновая работа показывает общий и файловый прогресс и отменяется безопасно. Все локальные данные (SQLite, модель, кэш) в каталоге данных приложения. Чистая macOS сборка открывается без Python.

Новый публичный репозиторий включает английский README с настоящим обезличенным screenshot, руководства RU/DE/EN, changelog, сборку/установку, права и сторонние уведомления, release ZIP и SHA256SUMS. Перед публикацией просмотреть весь Git diff/history, release tree, модель/бинарные зависимости, строки с персональными путями и изображения. Публичную сборку проверить на пустых настройках; аккаунт Telegram не заполнять.

**Приёмка:** полный unittest-набор, сборка и запуск готовой .app проходят; ZIP распаковывается; SHA-256 совпадает; privacy scan не находит личных данных/ключей/сессий. Сборка и документы в GitHub соответствуют локальному проверенному коммиту.
